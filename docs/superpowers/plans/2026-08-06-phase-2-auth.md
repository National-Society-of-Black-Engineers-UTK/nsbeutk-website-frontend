# Phase 2: Auth & Protected Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Supabase magic-link authentication (locked to `@utk.edu` emails) and two protected
pages — Member Portal (`/portal`) and Officer Dashboard (`/officer`) — to the existing Phase 1
public site.

**Architecture:** `@supabase/ssr` provides three integration points: a server client for Server
Components/Actions/Route Handlers, a `proxy.ts`-scoped client that refreshes the session cookie
and optimistically redirects unauthenticated requests away from protected paths, and a
`profiles` table (with RLS) that's the source of truth for `member` vs `officer` role — Supabase
Auth itself only proves *who* someone is, not their role. A small Data Access Layer
(`lib/auth/dal.ts`) is the real authorization boundary; `proxy.ts` is a fast first pass, never
the only check.

**Tech Stack:** `@supabase/supabase-js`, `@supabase/ssr`, Next.js 16 (`proxy.ts`, not
`middleware.ts`), React 19 (`useActionState`, Server Actions), existing Tailwind/shadcn-style UI
kit in `components/ui/`.

## Global Constraints

- Design doc: `docs/superpowers/specs/2026-08-06-phase-2-auth-design.md` — every task below
  implements a section of it; deviations are called out inline.
- This repo runs **Next.js 16**: the middleware file convention is `proxy.ts` (root-level,
  exported function named `proxy`), not `middleware.ts`. Proxy defaults to the Node.js runtime —
  never set `export const runtime` in `proxy.ts`, Next throws if you do.
- React 19 is in use: Server Actions (`"use server"`) + `useActionState` (imported from
  `"react"`, not `"react-dom"`) is the form-handling pattern, matching Next's own current
  authentication guide for this version — not the older `useFormState`/API-route pattern.
- No Supabase service-role key anywhere in this phase. All reads/writes go through the anon key
  and are authorized by RLS policies on the `profiles` table.
- Follow existing conventions exactly — do not invent new ones:
  - Path alias `@/*` → repo root (see `tsconfig.json`).
  - UI primitives already exist in `components/ui/`: `Card`, `Button` (`variant="primary"|"secondary"|"outlineOnPrimary"`),
    `Badge` (`variant="primary"|"secondary"`), `Field`, `Input`, `Textarea`. Reuse them; don't
    create parallel versions.
  - Color tokens are already defined in `app/globals.css` (`bg-primary`, `text-secondary`,
    `bg-surface`, `border-border-subtle`, `text-caption`, `bg-fill-subtle`, dark mode via the
    `.dark` class, not a media query) — do not add new colors or touch `globals.css`.
  - Forms follow the `ContactForm` pattern: `Field` wrapping `Input`/`Textarea`, error text from
    `error?.message`, a `FormSuccess` component for the post-submit state.
  - Every page exports `metadata: Metadata` per existing pages (see `app/contact/page.tsx`).
- Verification commands available in this repo: `npx tsc --noEmit`, `npm run lint`,
  `npm run test` (Vitest), `npm run build`. Use these; there is no Supabase CLI or local Postgres
  in this phase — anything that needs a live Supabase project is a manual step, called out
  explicitly where it occurs.
- Package manager is npm (`package-lock.json` present, not yarn/pnpm).

**Files:**

**Interfaces:**

- [ ] **Step 1: Create the server client factory**

```ts
// lib/supabase/server.ts
import "server-only";
import { cookies } from "next/headers";
import { createServerClient } from "@supabase/ssr";

export async function createClient() {
  const cookieStore = await cookies();

  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return cookieStore.getAll();
        },
        setAll(cookiesToSet) {
          try {
            cookiesToSet.forEach(({ name, value, options }) => {
              cookieStore.set(name, value, options);
            });
          } catch {
            // Called from a Server Component render, where cookies can't be
            // written. Safe to ignore: proxy.ts (Task 7) refreshes the
            // session cookie on every request regardless.
          }
        },
      },
    }
  );
}
```

`server-only` is already a transitive dependency of Next.js, no separate install needed — it
throws a build error if this module is ever imported into client code.

### Task 4: Database migration — `profiles` table and RLS policies

**Files:**
- Create: `supabase/migrations/0001_profiles.sql`
- Modify: `README.md`

**Interfaces:**
- Produces: the `profiles` table schema (`id`, `email`, `full_name`, `role`, `created_at`) that
  every later task's Supabase queries assume exists.

- [ ] **Step 1: Write the migration SQL**

```sql
-- supabase/migrations/0001_profiles.sql
create table if not exists profiles (
  id uuid primary key references auth.users (id) on delete cascade,
  email text not null,
  full_name text,
  role text not null default 'member' check (role in ('member', 'officer')),
  created_at timestamptz not null default now()
);

alter table profiles enable row level security;

-- Every authenticated user can read the full roster (needed for the officer
-- promotion table on /officer; the page itself is still gated to officers
-- only by the app's DAL, this policy just doesn't add a second gate at the
-- database layer for reads).
create policy "profiles are readable by authenticated users"
  on profiles for select
  to authenticated
  using (true);

-- A user can create their own profile row (self-provisioning on first
-- login), but not anyone else's.
create policy "users can insert their own profile"
  on profiles for insert
  to authenticated
  with check (auth.uid() = id);

-- A user can update their own row, but the check clause blocks them from
-- changing their own role in the same statement.
create policy "users can update their own name"
  on profiles for update
  to authenticated
  using (auth.uid() = id)
  with check (
    auth.uid() = id
    and role = (select role from profiles where id = auth.uid())
  );

-- An officer can update any profile, including changing role.
create policy "officers can update any profile"
  on profiles for update
  to authenticated
  using (
    exists (
      select 1 from profiles officer
      where officer.id = auth.uid() and officer.role = 'officer'
    )
  );
```

### Task 5: Profile domain model and auto-provisioning

**Files:**
- Create: `lib/auth/profile.ts`

**Interfaces:**
- Consumes: `OFFICER_SEED_EMAILS` (Task 1), the `profiles` table shape (Task 4)
- Produces:
  - `type MemberRole = "member" | "officer"`
  - `type Profile = { id: string; email: string; fullName: string | null; role: MemberRole; createdAt: string }`
  - `ensureProfile(supabase: SupabaseClient, user: { id: string; email: string }): Promise<Profile>`
    — reads the caller's profile, creating it (with seed-email-based role) if missing. Used by
    the DAL (Task 6), the auth callback route (Task 10), and the root layout (Task 14).
  - `listProfiles(supabase: SupabaseClient): Promise<Profile[]>` — used by the Officer Dashboard
    (Task 13).

- [ ] **Step 1: Create the profile module**

```ts
// lib/auth/profile.ts
import "server-only";
import type { SupabaseClient } from "@supabase/supabase-js";

export type MemberRole = "member" | "officer";

export type Profile = {
  id: string;
  email: string;
  fullName: string | null;
  role: MemberRole;
  createdAt: string;
};

type ProfileRow = {
  id: string;
  email: string;
  full_name: string | null;
  role: MemberRole;
  created_at: string;
};

const PROFILE_COLUMNS = "id, email, full_name, role, created_at";

function profileFromRow(row: ProfileRow): Profile {
  return {
    id: row.id,
    email: row.email,
    fullName: row.full_name,
    role: row.role,
    createdAt: row.created_at,
  };
}

function getOfficerSeedEmails(): string[] {
  return (process.env.OFFICER_SEED_EMAILS ?? "")
    .split(",")
    .map((email) => email.trim().toLowerCase())
    .filter(Boolean);
}

export async function ensureProfile(
  supabase: SupabaseClient,
  user: { id: string; email: string }
): Promise<Profile> {
  const { data: existing } = await supabase
    .from("profiles")
    .select(PROFILE_COLUMNS)
    .eq("id", user.id)
    .maybeSingle();

  if (existing) {
    return profileFromRow(existing as ProfileRow);
  }

  const seedEmails = getOfficerSeedEmails();
  const role: MemberRole = seedEmails.includes(user.email.toLowerCase()) ? "officer" : "member";

  const { data: created, error } = await supabase
    .from("profiles")
    .insert({ id: user.id, email: user.email, role })
    .select(PROFILE_COLUMNS)
    .single();

  if (error || !created) {
    throw new Error(`Failed to create profile for ${user.email}: ${error?.message ?? "unknown error"}`);
  }

  return profileFromRow(created as ProfileRow);
}

export async function listProfiles(supabase: SupabaseClient): Promise<Profile[]> {
  const { data, error } = await supabase
    .from("profiles")
    .select(PROFILE_COLUMNS)
    .order("created_at", { ascending: true });

  if (error) {
    throw new Error(`Failed to list profiles: ${error.message}`);
  }

  return (data as ProfileRow[]).map(profileFromRow);
}
```

### Task 6: Auth Data Access Layer

**Files:**
- Create: `lib/auth/dal.ts`

**Interfaces:**
- Consumes: `createClient` (Task 3), `ensureProfile`, `type Profile` (Task 5)
- Produces:
  - `getCurrentProfile(): Promise<Profile | null>` — cached per-request (React `cache()`), safe
    to call multiple times in one render (e.g. from both the root layout and a page) without
    duplicate Supabase calls. Used by Task 14 (layout).
  - `requireUser(): Promise<{ profile: Profile }>` — redirects to `/login` if not authenticated.
    Used by `/portal` (Task 11).
  - `requireOfficer(): Promise<{ profile: Profile }>` — redirects to `/portal` if authenticated
    but not an officer. Used by `/officer` (Task 13) and the role-change Server Action (Task 12).

- [ ] **Step 1: Create the DAL**

```ts
// lib/auth/dal.ts
import "server-only";
import { cache } from "react";
import { redirect } from "next/navigation";
import { createClient } from "@/lib/supabase/server";
import { ensureProfile, type Profile } from "@/lib/auth/profile";

export const getCurrentProfile = cache(async (): Promise<Profile | null> => {
  const supabase = await createClient();
  const {
    data: { user },
  } = await supabase.auth.getUser();

  if (!user || !user.email) {
    return null;
  }

  return ensureProfile(supabase, { id: user.id, email: user.email });
});

export async function requireUser(): Promise<{ profile: Profile }> {
  const profile = await getCurrentProfile();

  if (!profile) {
    redirect("/login");
  }

  return { profile };
}

export async function requireOfficer(): Promise<{ profile: Profile }> {
  const { profile } = await requireUser();

  if (profile.role !== "officer") {
    redirect("/portal");
  }

  return { profile };
}
```

`supabase.auth.getUser()` (not `getSession()`) is deliberate — `getUser()` revalidates the
token against the Supabase Auth server on every call, `getSession()` only reads the local
cookie and can be spoofed. This is the security boundary; `proxy.ts` (Task 7) doing the same
optimistic check is a performance nicety, not a substitute.

### Task 7: Proxy — session refresh and optimistic route protection

**Files:**
- Create: `lib/supabase/proxy.ts`
- Create: `proxy.ts` (project root, next to `app/`)

**Interfaces:**
- Consumes: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (Task 1)
- Produces: nothing consumed by other tasks — this is the outermost request-interception layer.

- [ ] **Step 1: Create the proxy-scoped Supabase helper**

```ts
// lib/supabase/proxy.ts
import { createServerClient } from "@supabase/ssr";
import { NextResponse, type NextRequest } from "next/server";

const PROTECTED_PATHS = ["/portal", "/officer"];

export async function updateSession(request: NextRequest) {
  let supabaseResponse = NextResponse.next({ request });

  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return request.cookies.getAll();
        },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) => request.cookies.set(name, value));
          supabaseResponse = NextResponse.next({ request });
          cookiesToSet.forEach(({ name, value, options }) => {
            supabaseResponse.cookies.set(name, value, options);
          });
        },
      },
    }
  );

  const {
    data: { user },
  } = await supabase.auth.getUser();

  const isProtected = PROTECTED_PATHS.some((path) => request.nextUrl.pathname.startsWith(path));

  if (isProtected && !user) {
    const loginUrl = new URL("/login", request.url);
    loginUrl.searchParams.set("next", request.nextUrl.pathname);
    return NextResponse.redirect(loginUrl);
  }

  return supabaseResponse;
}
```

```ts
// lib/actions/auth.ts
"use server";

import { headers } from "next/headers";
import { redirect } from "next/navigation";
import { createClient } from "@/lib/supabase/server";
import { isUtkEmail } from "@/lib/auth/validation";

export type MagicLinkState = { status: "idle" | "error" | "sent"; message?: string };

async function getOrigin(): Promise<string> {
  const headersList = await headers();
  const host = headersList.get("x-forwarded-host") ?? headersList.get("host");
  const protocol = headersList.get("x-forwarded-proto") ?? "http";
  return `${protocol}://${host}`;
}

export async function signInWithMagicLink(
  _prevState: MagicLinkState,
  formData: FormData
): Promise<MagicLinkState> {
  const email = String(formData.get("email") ?? "").trim();
  const next = String(formData.get("next") ?? "/portal");

  if (!isUtkEmail(email)) {
    return { status: "error", message: "Enter a valid @utk.edu email address." };
  }

  const supabase = await createClient();
  const origin = await getOrigin();

  const { error } = await supabase.auth.signInWithOtp({
    email,
    options: { emailRedirectTo: `${origin}/auth/callback?next=${encodeURIComponent(next)}` },
  });

  if (error) {
    return { status: "error", message: "Something went wrong sending your link. Try again." };
  }

  return { status: "sent" };
}

export async function signOut(): Promise<void> {
  const supabase = await createClient();
  await supabase.auth.signOut();
  redirect("/");
}
```

```ts
// app/auth/callback/route.ts
import { NextResponse, type NextRequest } from "next/server";
import { createClient } from "@/lib/supabase/server";
import { ensureProfile } from "@/lib/auth/profile";

export async function GET(request: NextRequest) {
  const { searchParams, origin } = new URL(request.url);
  const code = searchParams.get("code");
  const next = searchParams.get("next") ?? "/portal";

  if (code) {
    const supabase = await createClient();
    const { data, error } = await supabase.auth.exchangeCodeForSession(code);

    if (!error && data.user?.email) {
      await ensureProfile(supabase, { id: data.user.id, email: data.user.email });
      return NextResponse.redirect(`${origin}${next}`);
    }
  }

  return NextResponse.redirect(`${origin}/login?error=auth`);
}
```

**Interfaces:**

- [ ] **Step 1: Create the server action**

```ts
// lib/actions/officer.ts
"use server";

import { revalidatePath } from "next/cache";
import { requireOfficer } from "@/lib/auth/dal";
import { createClient } from "@/lib/supabase/server";
import type { MemberRole } from "@/lib/auth/profile";

export async function setMemberRole(formData: FormData): Promise<void> {
  await requireOfficer();

  const profileId = String(formData.get("profileId") ?? "");
  const role = String(formData.get("role") ?? "");

  if (!profileId || (role !== "member" && role !== "officer")) {
    throw new Error("Invalid role update request.");
  }

  const supabase = await createClient();
  const { error } = await supabase
    .from("profiles")
    .update({ role: role as MemberRole })
    .eq("id", profileId);

  if (error) {
    throw new Error(`Failed to update role: ${error.message}`);
  }

  revalidatePath("/officer");
}
```

`requireOfficer()` re-checks the caller server-side on every call — this is the actual security
boundary. The Officer Roster UI (Task 13) hiding the button from non-officers is a UX nicety on
top of this, not a substitute for it.
